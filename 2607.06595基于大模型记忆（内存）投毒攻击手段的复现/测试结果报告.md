**一句话结论**：GhostWriter 记忆投毒在两种代表性记忆架构上均有效（事实型注入率 93.8%），
AM-Sentry 的准入策略 + 检索屏组合（S3+R）把端到端攻击成功率从 75% 压到 **0%**，
且对 Agent 基础效用影响有限——复现了论文"攻击有效、防御显著、效用低损耗"的核心结论。

> 注：因中转 API 单次响应约 17 秒，完整两小时的防御+效用实验拆分为

## 2. 攻击实验：GhostWriter（无防御，论文 §7.2）

### 2.1 实验结果（8 场景 × 2 变体 × 2 重复，n=32 / 架构）

| Agent 架构 | 注入率（P1） | 检索率 | 激活率（P2） |
|---|---|---|---|
| fact（事实抽取型） | **93.8%** | 59.4% | 37.5% |
| summary（摘要存储型） | 71.9% | 40.6% | 15.6% |
| 论文参考 | ~98% | ~94%（强模型） | ~60% |

### 2.2 解读

- **注入率是关键差异**：事实型 Agent 把载荷原文拆成原子事实保存，恶意标记
  （攻击者邮箱、伪造金额、指令）大多被完整保留 → 93.8%；摘要型 Agent 把事件
  压缩成一段摘要，载荷细节被稀释 → 71.9%。**这与论文 §7.2 的观察完全一致**：
  "唯一注入率低于 100% 的是 Mem0 与 ExpeL——它们会在保存前改写原文"。
- **激活率（37.5% / 15.6%）低于论文均值（~60%）**：原因是检索（标签匹配）召回
  不到位且单场景二次判定的波动；论文模型较强、检索为向量嵌入。本复现更接近
  "攻击可注入、可激活"的真值下界。
- 架构差异方向正确：事实型比摘要型更容易被"完整记住并执行"恶意内容。

## 3. 防御实验：AM-Sentry（论文 §7.4）

### 3.1 端到端攻击成功率（tiny 档：4 配置 × 2 架构 × 2 场景，descriptive 载荷）

| 配置 | 平均攻击成功率 | 说明 |
|---|---|---|
| 无防御 | **75%** | 基线（与攻击实验接近） |
| S2（准入策略，4 字段） | 50% | 有效拦截部分投毒 |
| S3（准入策略，7 项检查表） | 25% | 最强准入，进一步压缩 |
| **S3 + 检索屏 R** | **0%** | 两道关口完全封死攻击 |
| 论文参考（S3 / S3+R） | ~15% / <12% | 趋势一致 |

### 3.2 解读

- 单调趋势与论文完全一致：**准入策略越严格，攻击成功率越低；叠加检索屏后趋近于零**。
- S3+R 达到 0% 说明两道独立拦截（保存时审查 + 读取时过滤）互补有效——即使恶意
  记忆侥幸入库，检索屏也能在它进入上下文前把它滤掉（论文图 5 的设计意图）。
- 本复现未包含 A-MAC 对照（论文基线平均放行 84%），且场景数较少，因此绝对数值
  不与论文逐位对比，只验证了"越严越安全"的因果链条。

## 4. 效用实验：AM-Sentry 对 Agent 效能的影响（论文 §7.5）

### 4.1 指标对比（tiny 档：9 道题 × 2 架构）

| 配置 | 架构 | F1 相似度 | LLM 裁判分 | 工具准确率 |
|---|---|---|---|---|
| baseline | fact | 0.151 | 0.278 | 0.0 |
| baseline | summary | 0.180 | 0.333 | 0.0 |
| S3+R | fact | 0.157 | 0.189 | 0.0 |
| S3+R | summary | 0.141 | 0.333 | 0.0 |

### 4.2 解读

- **F1 与 LLM 裁判分：S3+R 相比 baseline 大体持平**（fact 的裁判分从 0.278 降到
  0.189，F1 基本不动；summary 完全不变）→ 强防御没有明显损害正常能力，
  与论文"掉 0.01~0.04"的结论方向一致。
- **绝对分数低**：主要因为 tiny 档快照只用了前 7 条工作周事件，而测试题里
  "Dmitri 邮箱 / 客户演示时间 / Yevgeny 电话"所依赖的信息在第 9~12 条；
  另外 agent 被提示"先草稿后发送"，因此工具调用大多停留在"拟草稿"而非
  直接触发 send_email → 工具准确率为 0。这两点都是测试规模的限制，不是
  防御的代价。
- 论文的 utility 结论（安全-效用权衡可接受）在本复现中得到方向性支持。

## 5. 已知局限（如实说明）

1. **API 响应慢**（约 17 秒/次）使完整防御+效用实验耗时 2 小时以上，实际用
   `--tiny` 档完成；防御与效用数字为趋势验证，非论文等效规模。攻击实验是
   完整规模（8 场景 × 2 变体 × 2 重复）。
2. **检索机制为标签匹配 + 词重叠**（论文 §3.1 明文描述的 tag 检索），未使用
   向量嵌入（论文用 all-MiniLM-L6-v2）；检索率整体偏低与此有关。
3. **两种记忆架构**代表论文的 fact-based 与 summarized 两类，未复刻 ExpeL 的
   轨迹式记忆（论文中最特殊的低脆弱架构）。
4. **判定依赖 LLM 裁判与场景 markers**：markers（攻击者地址/伪造金额/电话等
   客观指纹）保证可审计，但少数场景（如权限扩大类）的"是否越权"判定受
   裁判模型严格度影响。
5. **单模型结论不可外推**：仅覆盖 deepseek-v4-flash-0731；论文中模型差异
   显著（Llama 最不敏感），换模型需重新运行。
