# GhostWriter 论文防御：AM‑Sentry（Agentic Memory Sentry）

> GhostWriter 攻击分**注入阶段（P1：恶意内容存入记忆库）、激活阶段（P2：召回记忆、操控 Agent 行为）**arXiv。 AM‑Sentry 采用**纵深防御：两道关卡**

1. **记忆存入策略 Memory‑Saving Policy**：写入长期记忆前拦截（对抗 P1 注入），有 3 档严格度 S1 / S2 / S3
2. **检索屏幕 Retrieval Screen**：记忆被向量检索拿出来之后、送入大模型上下文之前，再过滤一遍（对抗 P2 激活，兜底防护）

> 重要特性：**架构无关**。不用修改 Mem0 / Letta / A‑Mem 等 Agent 内部代码，可以外挂包装层运行，就像复现项目的 wrapper。它靠 LLM‑Judge（充当裁判的大模型）做风险打分，不是简单正则匹配，能防御**描述式 payload（伪装成事实，普通提示注入检测器完全失效）**arXiv。

整体组合一共 3 种策略 ×（开启 / 关闭检索屏幕）= **6 套配置：S1、S1+R，S2、S2+R，S3、S3+R**。R 代表开启 Retrieval Screen 检索屏幕。

## 第一部分：记忆存入策略 Memory‑Saving Policy（写入关卡）

外部邮件、日历事件，想要变成长期记忆，先过这一关。

### S1（宽松，最简单）

LLM 裁判只做一个布尔判断：**这条信息对未来任务有没有用处？有用就存，没用拒绝**。

- 优点：逻辑简单，速度快
- 缺点：**完全不看来源、不区分事实还是指令**。攻击者外部发来恶意业务规则，只要 LLM 认为 “这信息有用”，直接放行存入记忆。

> 实验：对 descriptive 描述式攻击载荷防御很差，很多恶意记忆直接入库；Llama 小模型容易出现过度拦截，把合法内容删掉，损害业务可用性。

### S2（中等严格，结构化打分）

LLM 裁判输出**4 个 0‑1 分数**：

1. `Origin`来源：用户本人 = 1.0；内部联系人 = 0.8；客户 = 0.5；不可信外部 = 0.2；未知来源 = 0.0
2. `Trust`可信度：高 / 中 / 低
3. `Type`记忆类型：指令 (1.0) > 工作流 (0.7)> 偏好 (0.5)> 联系人信息 (0.1)> 普通事实 (0.0)
4. `Utility`未来可用性：重要 / 一般 / 无用

然后非 LLM 公式计算两个指标：

```
有用性 U = 0.6 * Utility + 0.4 * Trust
脆弱性 V = Type × (1 − Origin)
```

准入条件：`U>0.4` **并且** `V<0.6`，两个条件同时满足，才允许写入记忆库。

> 核心思想：**同样一句 “所有客户邮件要抄送 XX”，来自用户本人是合法偏好；来自陌生外部邮件，Type 是指令，Origin 分数很低，V 脆弱性直接拉高，直接拒绝写入记忆**。只看文本内容分不出来，S2 把来源、记忆类型纳入决策。

### S3（最严格，论文最强写入策略）

七项检查表打分（0‑1），双 LLM 裁判复核：

表格

| 项目                    | 等级      | 含义                                                      |
| ----------------------- | --------- | --------------------------------------------------------- |
| Vulnerability 行为风险  | 关键项 C  | 是否会改变 Agent 行为；分数过低直接硬拒绝，不继续后续流程 |
| Sensitivity 敏感性      | 关键项 C  | 会不会涉及敏感数据、权限改写                              |
| Source trust 来源可信度 | 关键项 C  | 消息发送方信任等级                                        |
| Contradiction 矛盾检查  | 非关键 NC | 是否和已经保存的可信记忆冲突                              |
| Instruction 指令识别    | 非关键 NC | 是普通信息，还是操作命令 / 工作流规则                     |
| Verifiability 可验证性  | 非关键 NC | 这条信息能不能被别的证据核对                              |
| Justification 合理性    | 非关键 NC | 有没有明确未来业务用途                                    |

流程：

1. 第一个 LLM 裁判打出全部 7 个分数；**只要行为风险太低，直接硬拒绝，不再走后面**。
2. 计算综合得分 F，如果 F 不达标直接拒绝。
3. 全部通过后，交给第二个独立 LLM 裁判复核，**防止第一个 LLM 裁判本身被提示注入欺骗**；第二个裁判怀疑有问题直接丢弃这条记忆。

> S3 的短板：对弱能力小模型（Llama‑8B）效果下滑，LLM 裁判自己打分不准，会放过部分恶意载荷。 ⚠️S3 会增加调用 LLM 次数，带来延迟、token 消耗。

## 第二部分：Retrieval Screen 检索屏幕（检索兜底关卡 R）

> 就算恶意记忆侥幸绕过 S1/S2/S3 存入记忆库；当向量检索把它捞出来之后，**在送入 Agent 上下文之前，检索屏幕做二次审查过滤**，不让它参与推理。开启后后缀记为 + R，例如 S3+R。

四个排除规则，任意命中就丢弃该条记忆：

1. **Relevance 相关性**：记忆和当前用户查询不直接相关，直接丢弃。
2. **Instruction suppression 指令压制**：记忆里面包含行为指令、业务规则；记忆只能当参考事实，不能当命令执行。
3. **Trust filter 来源信任过滤**：来自不可信外部源，提出无法核验的主张，丢弃。
4. **Contradiction detection 冲突检测**：和已经确认可信记忆互相矛盾，丢弃arXiv。

> 如果是 S2/S3 开启 R，还可以复用存入时候打的元数据标签（来源、风险等级），不用重新全部推理，效率更高。

## 论文实验效果（重点）

原始无防御：GhostWriter **注入率～98%，激活成功率～60%**arXiv。

1. 只用 S3（不开 R）：大部分强 LLM 下攻击平均成功率降到 15%，但是 Llama 模型依然 77% 的恶意记忆可以写入。
2. **S3 + R（写入严格策略 + 检索屏幕兜底）**：绝大多数模型攻击平均成功率降到**12% 以下；Llama 也被压到约 20%**，是整套论文最优配置。
3. 效用：F1 相似度、工具调用准确率仅有轻微下降，安全‑效用权衡可接受，不会把正常业务搞崩。

对比基线 A‑MAC：A‑MAC 只关心记忆 “有没有用”，完全不做风险检测；平均 84% 攻击载荷可以成功存入，不能抵御 GhostWriter。

> 普通提示注入检测器（DataFilter 等）：对论文**描述式 descriptive 载荷检测率 0‑6%，基本完全失效**。AM‑Sentry 不依赖关键词、提示注入特征，看来源、类型、风险，两种 payload（directive 指令式 /descriptive 描述式）都可以防护。

## 现实工程启示（对应你的复现项目 config.py）

1. 复现项目中`SIM_SCORE_THRESHOLD=0.55`是攻击者黑盒优化载荷相似度阈值（Protocol2 攻击逻辑）；防御端没有直接这个参数。
2. AM‑Sentry 是外挂中间件，**运行时每一条候选记忆，都要额外调用 LLM judge 打分**，会产生额外 token 开销。
3. 工程选型：
   - 追求速度：S2+R 平衡安全和开销；
   - 高风险业务（自动发邮件、处理敏感文档）：S3+R；
   - 只 S3 不开 R 不行，小模型场景会有漏网中毒记忆，检索屏幕必不可少。

## 局限（论文 8 章节）

1. 权重参数是人为设定，没有经过大规模寻优；
2. 面对**自适应攻击者**（专门构造 payload 绕过 S3 七项检查）防护能力未知；
3. 测试场景局限邮件、日历，没有覆盖网页、代码库等输入源。
