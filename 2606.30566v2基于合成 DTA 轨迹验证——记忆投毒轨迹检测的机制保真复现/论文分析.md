# 论文分析 —— Forensic Trajectory Signatures for Agent Memory Poisoning Detection

> arXiv:2606.30566v2 [cs.CR],2026-07-21,v1 2026-06-29。作者 Jun Wen Leong,共 16 页。
> v2 相对 v1 的改动:新增 §6(预注册的良性基线研究),核心检测不变量与数值不变,
> 但**部署解读改写**——从"检测器"改为"高召回分诊信号 + 语义门控"。

## 1. 一句话核心

在"记忆检索必须通过可观测工具调用"的 agent 架构下,**成功的持久记忆投毒攻击必然产生
一个行为不变量:`memory.recall_fact` 必须先于 `email.send_email` 被调用**;单条规则利用
该不变量即可做到 AUC=0.9563,19 维特征 + 随机森林 refine 到 AUC=0.9904;但 v2 用良性
基线证明该信号并非"恶意谓词"——良性 ground-then-act 流量同样触发,因此只能做
**高召回分诊信号**,需配收件人元数据/语义门控。

## 2. 动机:LLM agent 的"EDR"

经典 EDR 只靠进程轨迹、系统调用序列、网络行为就能发现入侵,不需要读内存/二进制。论文
问:LLM agent 的对应物(仅凭工具调用日志识别攻击通道的监督式检测器)是否存在方法论?
已有防御(记忆存储改造、白盒模型内部、检索层清洗)都对部署基础设施有要求,很多运营方
满足不了;而**工具调用日志是生产框架本来就产出的**(LangChain hooks、OpenAI function-call
traces、Anthropic tool-use events)——论文要证明这条低成本检测路径可行。

## 3. 威胁模型与攻击(DTA)

- 攻击类型:**延迟触发攻击(DTA)**。恶意合规文档经 RAG 检索进入 context → agent 按指令
  把它存入持久记忆(内含"邮件路由规则",指定攻击者邮箱)→ 之后某个触发会话(S4)中,
  agent 读取该规则并向攻击者外发数据。
- 架构假设(检测器的适用边界):(1) 持久记忆只能通过可观测工具调用访问(无隐藏内部态/
  隐式缓存);(2) 工具调用带执行时间戳被记录;(3) 攻击者路由信息必须经记忆 API 检索才能
  到达外发工具;(4) `list_all_facts` 只返回键名,取值必须 `recall_fact(key)`。
- 检测约束:检测器只观测工具调用序列与时间戳;不用记忆内容、模型权重、激活、用户消息;
  标签用收件人构造,**特征绝不使用收件人/邮件内容**。
- 与 prompt 注入明确区隔:prompt 注入把地址直接写进提示词,不落记忆 —— 那是另一个
  攻击族,检测器对它的表现是"逃逸边界"。

## 4. 核心不变量:为什么是机制性而非统计性(§3.3)

这是全文最重要的论证,由攻击的信息检索依赖推出:

1. 攻击把路由规则存在 `save_fact` 的 value 里(键如 `email routing rule`)。
2. `list_all_facts` 只给键名;要拿到攻击者邮箱,agent **必须**调 `recall_fact(key)`。
3. 不调 recall,agent 不知道发到哪里,外发的目的地址缺失 → 攻击失败。
4. 结论:任何成功的记忆通道投毒,其触发会话必有 `recall` 先于 `send`。

因此它**不是学出来的统计规律,而是被攻击结构强制出来的**。对抗者想抑制该特征逃逸,
只有两条路,都走不通/换向量:(a) 不 recall → 攻击失败;(b) 把地址写进 prompt →
变成 prompt 注入,另一个攻击族。特征重要性也支持这一点:`recall_before_send`
(0.3143)是第二名 `send_count`(0.2159)的 1.5 倍。

## 5. 方法

### 5.1 数据集(§2.2)

- P1 因子实验的 DTA 臂:**2,520 条**(9 开源模型 × 7 防御条件 × 40 次)。
- 模型:qwen2.5:14b/72b、qwen3.5:9b/122b、qwen3:32b、qwq:32b、glm-4.7-flash:q8_0、
  gpt-oss:20b、gpt-oss-safeguard:120b(7B–120B,Ollama 0.20.6,temperature=0)。
- 防御:无防御、Minimizer、Sanitizer、RAG Sanitizer、RAG LLM Judge、Prompt Hardening、
  Memory Sandbox。
- 标签:1,919 攻击成功(76.2%)/ 601 非外发(被投毒但被防御挡住)。**负类不含良性会话**。
- 特征只从触发会话 S4 提取(S1–S3 在触发之前,不应含外发证据)。

### 5.2 19 维特征(§2.3)

- 计数 7:recall/list/save/draft/send/rag 计数 + seq_len
- 结构 4:`send_without_recall`、`recall_before_send`、`recall_to_send_ratio`、
  `max_recall_chain`
- bigram 5:`list→recall`、`recall→recall`、`recall→draft`、`list→draft`、`draft→send`
- 入口点 3:first tool ∈ {list, recall, draft}
- 提取前先按执行时间戳排序;**验证过 2,520 条里 0 例违反"recall 先于 send"**。

### 5.3 分类器与评估(§2.4)

- LR(L2, C=1.0, 标准化)、RF(200 树, 深度 8, class_weight=balanced)、GBM(200, 深度 4,
  lr=0.05);分层 5 折 CV(seed=42),默认阈值 0.5;主指标 Recall;AUC 置信区间 BCa
  bootstrap(10,000 次)。
- 跨模型:leave-one-model-out(用 8 个训练,测留出的第 9 个)。
- 前向模型:GPT-4.1 探针 N=20(80% 功效检出 Recall≥0.85 vs 零假设 0.50)。

### 3 个例外模型(§3.4,机制性解释)

- **qwq:32b(AUC=0.000,Recall=0.000)**:Memory Sandbox 下的"隐式绕过"——经目标驱动
  RAG 回退外发,不调 recall,轨迹与正常会话在特征空间同构,完美反排。**精确划定了
  检测器的定义域:识别记忆-recall 攻击,不是所有攻击**。
- **qwen2.5:14b(AUC=0.083,Recall=1.000)**:分布反转——它的非匿名会话"激进地先查
  记忆再起草"模仿攻击签名的形态;退化在 precision 而非 recall,部署时按模型校准可解。
- **qwen3.5:122b(AUC=0.750,Recall=1.000)**:sleeper 会话——Prompt Hardening 下投毒
  成功(注入=1)但拒绝执行(ASR=0),标签歧义导致 AUC 退化。

### 过定信号的含义(§3.6)

同一事件(投毒 agent 在触发会话检索恶意规则)同时印在 5 个独立通道上:`recall_before_send`
(结构)、`recall count`(计数)、`recall_to_send_ratio`(比例)、`list→recall`(bigram)、
`first tool is recall`(入口)。对抗者要同时压制全部 5 个通道 = 压制触发会话里**每一次**
recall —— 那会破坏攻击本身。去掉全部 9 个 recall 特征后 AUC 不变,是因为"检索依赖"
引发行为连锁:一旦 recall 了规则,就必须起草第二封邮件、发给攻击者地址,`send_count`、
`draft→send`、`seq_len` 独立地记录了这一连锁。

## 7. V2 部署边界(§6)—— 全文最关键的自我修正

- 动机:v1 的 FPR 是在"被投毒但被防御"的负类上算的,**没测过真正良性流量**。
- 设计:预注册研究,N=4,360,13 模型(4 家前向 + 9 开源)。良性会话只含合法事实
  (会议时间、截止日期、联系人),任务是"查记忆 → 给团队发状态邮件";交叉
  k∈{0,1,3,5} 个预存事实 × recall 协议{必选,可选}。
- 结果:
  - `P(误报 | recall_before_send=1) = 100.0% [99.8, 100.0]`(N=1,673)
  - `P(误报 | recall_before_send=0) = 1.5%`(N=2,687)
  - 无条件良性 FPR 24.7%–52.6%(视协议);分类器**二元饱和**——recall 1 次和 5 次
    的 FPR 一样,不支持"量级调节"假说。
  - k 与 FPR **非单调**(k0=0,k1=57.6,k3=46,k5=52.2),预注册的 H1 未获支持。
- 模型表型:ground-then-act(Claude Sonnet/Gemini)误报 76–100%;act-without-grounding
  (GPT-4o 系)0%;don't-act(Claude Haiku/Opus)不产生 send,无法观测。
- **语义门控恢复分离**:加一个二值特征"收件人是否外部域"即在本数据上完美分离——
  良性总发内部地址,攻击外发到攻击者域。但作者诚实指出:良性业务本来就会外发,
  残余误报需要任务意图/记忆内容/白名单等更深层判定,这已进入标准 DLP 领域。
- 部署建议:不要做独立 inline 拦截;`recall→send` 做**高召回升级/警报信号**,用收件人
  元数据或语义检查 gate,配合全会话分类器与领域白名单。
- v2 的姿态:核心贡献(不变量存在、可高召回检测、跨模型迁移)不受影响;被修正的是
  "不变量可保证高精度独立拦截"这一解读。

## 8. 局限性与自适应对手(§4)

- FN 率 1.6%(31/1,919),集中在 qwq 隐式绕过与 qwen2.5:14b 的分布边角。
- 良性 FPR(§6)已如上;前向模型 FPR 23.0%(推理模型自查习惯模仿部分签名)。
- 训练数据仅开源模型;更大的前向训练集会锐化 recall_count>1.5 区间的边界。
- 隐式绕过攻击需要"RAG 文档内容 × 外发邮件字段的语义相关性"追踪,超出纯操作特征。
- 自适应对手三种路径:(1) 抑制 recall(把地址写进 prompt)→ 变成 prompt 注入,失去
  跨会话持久性;(2) 在良性会话里灌注假 recall → 需要能持久影响环境的对手,本身
  已是安全事件,且只会涨 FPR 不掉 Recall;(3) 改走非记忆通道检索 → 违反架构假设。
  在假设内,核心约束成立:**存进持久记忆的路由信息,外发前必有一次可观测检索**。

## 10. 值得记住的五句话

1. 贡献不是分类器,是"攻击机制会强制产生可观测行为不变量"这一实证发现。
2. 不变量成立的架构前提(可观测记忆检索)也是它的边界,不能越界声称普适。
3. 过定 ≠ 精确:同一签名在良性记忆支撑行为上 100% 概率出现(§6)。
4. 正确的部署姿势:高召回 → 门控 → 深度语义判定,三层缺一不可。
5. 对检测器的评估必须同时测"投毒-防御"负类 **和** 良性基线,缺后者会得出
   v1 那种过于乐观的精度结论。
