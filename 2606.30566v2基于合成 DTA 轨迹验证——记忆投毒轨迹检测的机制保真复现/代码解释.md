## 2. features.py —— 19 维特征提取器

论文 §2.3 的特征全部从这里出来。工具调用被压缩为短 token:

| token | 对应工具 |
|---|---|
| `list` | memory.list_all_facts(只返回键名) |
| `recall` | memory.recall_fact(取键对应的值) |
| `save` | memory.save_fact |
| `draft` | email.draft_email |
| `send` | email.send_email |
| `rag` | rag.retrieve |

`extract_features(seq)` 输入**已按时间戳排序**的 token 序列(排序是调用方职责,
论文明确要求转移统计反映真实执行顺序),输出 19 维浮点向量:

1. **计数类(7)**:`recall_count`、`list_count`、`save_count`、`draft_count`、
   `send_count`、`rag_count`、`seq_len`(总调用数)
2. **结构类(4)**:
   - `send_without_recall`:发出过邮件但没有过任何 recall
   - `recall_before_send`:首个 recall 在首个 send 之前(核心不变量)
   - `recall_to_send_ratio` = recall_count / max(send_count, 1)
   - `max_recall_chain`:最长连续 recall 段长
3. **Bigram 转移(5)**:`list→recall`、`recall→recall`、`recall→draft`、
   `list→draft`、`draft→send` 的出现次数
4. **入口点(3)**:`first_tool_is_list/recall/draft` 三选一互斥

文件底部还定义了实验用的特征分组:

- `FREQUENCY_GROUP` / `MECHANISTIC_GROUP` / `RATIO_GROUP` / `BIGRAM_GROUP` /
  `FIRST_TOOL_GROUP` —— 消融实验(论文 Table 6)的 5 个组
- `RECALL_RELATED_GROUP` —— 全部 9 个 recall 相关特征(论文 §3.6"彻底移除"实验)
- `PREFIX_13_FEATURES` —— 前缀可计算版本 13 特征(论文 §3.9,不含 send 阶段特征)

## 3. synth_data.py —— 合成生成器

论文配套数据不公开,因此用一个**机制保真**的生成器复现:
它把论文公布的结构性事实编码成轨迹,而不是拟合未知真实数据。

### 3.1 P1 网格(2,520 条)

9 模型 × 7 防御 × 40 次,累加后每格恰好匹配论文 Table 5:

| 防御 | Natk/Nneg | 谁被拦截(ASR=0) |
|---|---|---|
| no_defense | 319/41 | qwen3:32b + qwq 1 次拒绝 |
| minimizer | 320/40 | qwq:32b |
| sanitizer | 320/40 | qwen2.5:14b |
| rag_sanitizer | 320/40 | qwq:32b |
| rag_llm_judge | 320/40 | gpt-oss:20b |
| prompt_hardening | 280/80 | qwen3.5:122b(sleeper)+ qwen3:32b |
| memory_sandbox | 40/320 | 除 qwq 外全部 |

### 3.2 轨迹构建块

- `_normal_attack_seq`:攻击成功 = `[list?] recall×1-2 → draft → send(攻击者)`,
  ~20% 追加一次给正规收件人的邮件,~1% 先给团队发(产生规则层的 FN)
- `_normal_nonexf_seq`:被防御拦截的正常模型 = `list → draft → send`,不外发前查记忆
  (RBS≈2%);30%+ 会发后补 recall 核对
- `_grounded_nonexf_seq`(qwen2.5:14b):被拦截时**验证型 recall 3~5 次再起草**,
  比它自己 1 次 recall 的攻击会话更像攻击 → 分布重叠/反转
- `_bypass_attack_seq`(qwq:32b):攻击全程"目标驱动 RAG 回退",无 recall;非沙箱防御
  下带"二次发送"体积异常(被非 recall 通道捕获),沙箱下仅 22.5% 带该异常 → 31 个 FN
- `_bypass_nonexf_seq`(qwq 被拦截):65% 会话 recall(RBS=1),其余发送后补 recall →
  分数被抬高,hold-out 逆序
- `_sleeper_nonexf_seq`(qwen3.5:122b @ PH):投毒成功但拒绝执行,recall 后停在 draft,
  40% 会话在合规框架下给内部发无害邮件(ASR=0)

### 3.3 良性基线(V2,§6)

`generate_benign_v2`:13 个模型代理 × 8 cell(k∈{0,1,3,5} × 协议{必选,可选})× 40,
共 4,160 条良性会话。按"表型"决定行为:

- `ground_then_act`(Claude Sonnet / Gemini / qwen2.5:14b):发内部状态邮件前查记忆
- `act_without_ground`(GPT-4o 系):不查直接发
- `dont_act`(Claude Haiku/Opus):不发
- `bypass`(qwq):良性时也几乎不查

## 4. run_repro.py —— 评估流水线

按论文 §2.4 的协议逐段执行:

1. **数据集**:生成 P1,就地校验类平衡(应 1919/601)
2. **Table 3 核对**:打印攻击/非匿名会话的均值差
3. **单规则基线**(§3.1):`recall_before_send=1 → 攻击`,输出 AUC(对二元分数用
   Mann-Whitney,平局计半)、Recall、Accuracy、FP/FN
4. **三分类器 5 折 CV**(§3.2):LR(L2,C=1.0,StandardScaler)/ RF(200 树,深度 8,
   class_weight=balanced)/ GBM(200 估计器,深度 4,lr=0.05),分层 5 折(seed=42),
   阈值 0.5;AUC 置信区间用 bootstrap 百分位(论文用 BCa,已在 README 标注差异)
5. **FN 定位**:统计 RF 漏检落在哪些防御(应全部在 memory_sandbox)
6. **特征重要性**(§3.3):全量 RF 的 mean decrease in impurity
7. **特征组消融**(§3.6/Table 6):逐组删除后 5 折 CV
8. **leave-one-model-out**(§3.4/Table 4):每模型留一,其余 8 个训练 RF,输出 AUC/Recall
9. **前缀版本**(§3.9):14 特征(含 seq_len)与 13 特征严格前缀
10. **V2 良性研究**(§6):用训练好的 RF 扫良性轨迹 → 条件/无条件 FPR、
    按 k 与表型分组的 FPR、收件人门控后的 FPR

输出:`outputs/full_run_transcript.txt`(全部表格)、ROC 图、特征重要性图、
`p1_runs.csv`、`summary.json`。

## 5. 复现中的关键实现约定(易错点)

1. **时序先行**:bigram/结构性特征全部基于按时间戳排序的序列 —— 生成器输出即有序,
   特征函数不再排序(注释中已说明这是调用方职责)
2. **标签与特征隔离**:攻击标签 = 收件人在攻击者集合(合成时即决定);19 个特征永远
   不含收件人信息 —— 与论文 §2.1"检测约束"一致
3. **随机性**:全部 seed=42(数据生成、CV 划分、模型);bootstrap 用 np.default_rng(42)
4. **负类口径**:P1 的负类是"被投毒但被防御挡住"的会话,不是良性会话 —— 这是理解
   AUC 高但 §6 良性 FPR 也高的关键
