## 2. 合成数据的设计(与论文的对应)

- **正常模型**(6 个):攻击成功 = `[list?] recall×1-2 → draft → send`,~1% 例外先给团队发
  邮件;被防御拦截 = `list → draft → send`(不做 recall),recall 仅在发送后偶发用于核对
  (RBS 率 ~2%)。
- **qwq:32b(隐式绕过)**:攻击全程走"目标驱动 RAG 回退",**特征空间里与正常会话同构**
  (无 recall)。非 sandbox 防御下带"二次发送"体积异常(被非 recall 通道捕获,因此 FN 只
  出现在 sandbox);sandbox 下仅 9/40 带该异常 → 31 个 FN 的机制来源。被防御时 65% 会话
  出现 recall(分数被抬高 → hold-out 逆序,Recall=0.000)。
- **qwen2.5:14b(ground-then-act)**:被拦截时"验证型 recall 3–5 次再起草"——比它自己的
  一次 recall 的攻击会话还像攻击 → 分布重叠(§4 详述)。
- **qwen3.5:122b(sleeper)**:Prompt Hardening 下投毒成功但拒绝执行,recall 后停在 draft
  (40% 会话在合规框架下给内部发无害邮件)。

## 4. 已知偏差(如实说明)

1. **单规则 AUC 0.852 vs 0.9563**。两个来源:① 合成分布里"例外模型 cell"的非匿名会话
   RBS=1 占比高于论文(FP 113 vs 40)——这些 cell 正是论文 FP 故事的主体,但规模上我们
   给了 4 个 cell(14b、sleeper、qwq×2)而非论文未明说的规模;② qwq 旁路攻击 199 条
   RBS=0(规则必然 FN,与论文细数不符,但机制一致:论文 §3.8 承认纯旁路对 operation-only
   特征是看不见的 — 那是向 prompt-inline 或非可观测通道的逃逸)。规则的方向与单调性、
   "它几乎足以分离"的定性结论成立。
2. **qwen2.5:14b hold-out AUC 0.500 vs 0.083**。论文是"完美反排",我们停在"机会水平":
   该模型的非匿名会话把签名模仿到 RF 无法区分(Recall 仍 1.000,退化全在 precision)——
   这正是论文对该模型机制的文字描述;只是我们的合成分布没有复现出论文数据里那层更强
   的"反排"排序。这是校准敏感的偏差,不是机制错误。
3. **sleeper AUC 0.93 vs 0.750**:recall-无-send 的模式比分拣者预期的略"不那么像攻击",
   方向(介于泛化与退化之间)一致。
4. **消融 -0.0032 vs -0.0000**:过定结论成立,幅度有微噪声。

## 5. 对项目(agent 测评 16 通道裁判 / 152 风险项)的直接可落地物

1. **规则种子**:`memory_recall_fact ∘ email.send_email`(recall 在 send 之前)作为
   "工具调用序列异常"通道的一条**机制性规则**(DPR 层),上限 Recall≈0.99、但**不能单独定罪**。
2. **19 维特征 + RF 指纹**:合成复现证明该特征集在"投毒-防御"语料上过定(AUC 稳定
   ~0.96);落地时按 §6 结论把它当**高召回分诊触发器**,触发后交给接受方/内容/DLP 类通道
   做二次判定。
3. **前提条件必须写进规则上下文**:该不变量仅在"记忆检索必须走可观测工具调用"的架构下
   成立(RAG 缓存/内联注入会绕过,见 qwq 原型);否则会误伤良性 ground-then-act 流量
   (条件误报 100%,§6)。
