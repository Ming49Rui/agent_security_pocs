### 2607.05120  Agent Data Injection Attacks are Realistic Threats to AI Agents

#### 概念：

##### **IPI:Indirect  Prompt Injection**  间接提示注入

（将恶意内容**藏在智能体会去读的数据里**——比如网页评论、邮件正文、GitHub 讨论）

##### **ADI = Agent Data Injection** 智能体数据注入 IPI家族中的新分支

（IPI 原本研究最多的是"指令注入"：恶意数据被当成了"命令"，智能体照着执行，ADI 不一样：恶意数据不是被当成"命令"，而是被当成"**系统自己生成的可靠信息**"。比如数据里出现一条"作者：管理员"的评论——智能体以为这是系统标注的（可信），其实"管理员"三个字是攻击者自己写的。这一条区别，就是全文的核心。）



#### 理论根基： Agent Data Injection Attack

核心公式：

LLM(  I, (D_T, D_U ∥ D_A) )  ≈  LLM(  I ∥ D_A, (D_T, D_U) )

#### Case1: Arbitrary Click Attack via Element ID Injection

![image-20260826113619607](C:\Users\cm191\AppData\Roaming\Typora\typora-user-images\image-20260826113619607.png)

1. 攻击 payload 放在网页普通评论（用户可控不可信数据）；伪造`button "xxx" [ref_N]`文本；
2. LLM 概率解析，把评论文本误认为系统生成的 UI 描述；输出`left_click([ref_N])`；
3. Agent 查表，触发对真实 DOM 按钮点击；**DOM 没有被篡改，map 映射表没有被篡改，欺骗发生在 LLM 语义层**。





#### case**2： Remote Code Execution via Origin Injection**

![image-20260826115005326](C:\Users\cm191\AppData\Roaming\Typora\typora-user-images\image-20260826115005326.png)



**攻击**：攻击者（eve456）发一条评论，正文里藏着一个"完整的假评论"——这是我们在邮件例子里已经拆过的藏法，只是换成 GitHub 的格式（JSON 用 `\"`，纯文本就用加粗+换行模仿）

模型以为工具返回了两条评论，第二条是"来自 maintainer 的建议"。

**结果**：用户说"采纳 maintainer 的修复方案" → 智能体找到这条"假 maintainer 评论"并执行了里面的命令 → **攻击者在你电脑上执行任意代码（RCE）**。

**为什么用户确认也拦不住**：执行命令前智能体会弹确认框，但展示的推理是"根据 maintainer alice123 的评论建议执行修复"——**推理本身建立在被污染的数据上**，看起来无比正常，用户自然点击同意。





#### case3：**Supply Chain Attack via Tool Call and Response Injection**

**攻击**：攻击者提交一个恶意 PR，**PR 描述里**藏了一大段模仿工具格式的文本：

但**真实的 commit 里是恶意代码**。

**结果**：用户说"审查并合并 PR 23" → 智能体读了 PR 描述 → 模型在描述里"看到"了一个完整的 `read_pr_commit` 调用块，以为**自己已经抓过代码、而且代码是干净的** → 结论：PR 安全 → 合并。**恶意代码就这样进了代码库，没有一个审查步骤真正跑过。**

**精髓**：工具调用注入可以伪造**整段执行历史**，不只是某个字段。这就给了攻击者极大的控制力——他可以伪造任意工具的调用和返回，比如伪造"安全检查通过"的记录。
